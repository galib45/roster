<objective>
## Goal

Stand up a runnable desktop application: `gpui-kit` renders a window with the roster navigation shell, and an organization created in the UI survives a save → restart → open cycle through a JSON project file.

## Purpose

De-risks the two foundations every later phase depends on — the GPUI Kit dependency set (which pins `gpui-pre` rather than the crates.io `gpui`) and the project file format. Once this plan is done, Phase 2's domain model and Phase 5's UI screens have a building, rendering, persisting app to grow into.

## Output

- Crate split into library (`src/lib.rs`) + GUI binary (`src/main.rs`)
- Pinned dependency set: `gpui-kit` 0.10, `pumpkin-solver` 0.5, `serde`, `serde_json`, `uuid`, `chrono` (serde)
- Minimal domain (`ProjectFile`, `Organization`) and JSON store with round-trip tests
- GPUI window: sidebar navigation + organizations page with add / save / open
- Prototype CLI preserved under `legacy/` as frozen reference
</objective>

    Restructure the crate and prove GPUI Kit builds on this machine before writing any feature code.

    1. Cargo.toml:
       - Add `gpui-kit = "0.10.0"`, `pumpkin-solver = "0.5.0"`, `serde = { version = "1", features = ["derive"] }`, `serde_json = "1"`, `uuid = { version = "1", features = ["v4", "serde"] }`.
       - Change chrono to `chrono = { version = "0.4", features = ["serde"] }`.
       - Keep `name = "roster"` and `edition = "2024"`. Do NOT add a direct `gpui` or `gpui-pre` dependency — `gpui-kit` owns that pin.
    2. Preserve the prototype: create `legacy/` and move `src/models.rs`, `src/utils.rs`, `src/main.rs` into it. Add `legacy/README.md` stating these files are a frozen, non-compiled reference for the solver semantics and will be ported in Phase 2. Use `git mv` so history follows the files.
    3. Create `src/lib.rs` with a crate doc comment only (modules arrive in Task 2) — this makes the package expose both a lib target and the `src/main.rs` binary.
    4. Replace `src/main.rs` with a minimal GPUI Kit window:
       - `use gpui_kit::component::label::Label; use gpui_kit::*;`
       - `struct RosterApp;` implementing `Render` returning `div().size_full().child(Label::new("roster"))`.
       - `application().with_assets(assets::Assets).run(|cx| { init(cx); open_window(WindowOptions::default(), cx, |_, cx| cx.new(|_| RosterApp)).expect("failed to open window"); })`
       - Call `init(cx)` before `open_window` — components are unusable without it.
    5. Build and run. The first build compiles GPUI and is expected to take several minutes.

    Avoid: adding `gpui = "0.2"` to make an example compile — examples written against crates.io `gpui` will not typecheck against `gpui-pre`. If GPUI Kit fails to build on Windows, stop and report the exact error as a blocker rather than switching UI frameworks.
  </action>
  <verify>`cargo build` exits 0; `cargo tree -d` shows a single `gpui-pre` version; `cargo run` opens a window displaying "roster"</verify>
  <done>AC-1 satisfied: one pinned GPUI set builds; AC-2 partially satisfied: window opens</done>
</task>

<task type="auto">
  <name>Task 2: Project file domain type and JSON store with tests</name>
  <files>src/lib.rs, src/domain/mod.rs, src/domain/project.rs, src/store/mod.rs</files>
  <action>
    Build the persistence core headlessly — no UI in this task.

    1. `src/lib.rs`: declare `pub mod domain;` and `pub mod store;`.
    2. `src/domain/mod.rs`: `pub mod project;` and re-export `pub use project::{Organization, ProjectFile, SCHEMA_VERSION};`.
    3. `src/domain/project.rs`:
       - `pub const SCHEMA_VERSION: u32 = 1;`
       - `ProjectFile { schema_version: u32, app: String, saved_at: DateTime<Utc>, organizations: Vec<Organization> }` deriving `Serialize, Deserialize, Clone, Debug, PartialEq`.
       - `Organization { id: String, name: String }`, same derives.
       - `ProjectFile::new()` sets `schema_version`, `app: "roster"`, `saved_at: Utc::now()`, empty orgs.
       - `ProjectFile::add_organization(&mut self, name: &str) -> &Organization` trims the name, generates `id` with `Uuid::new_v4()`, updates `saved_at`. Trimmed-empty names are rejected by returning the existing state — enforce this in the UI instead if a Result complicates the signature; do not silently store " " as a name.
    4. `src/store/mod.rs`:
       - `StoreError` enum: `Io(std::io::Error)`, `Json(serde_json::Error)`, `UnsupportedSchema(u32)`. Implement `Display` and `std::error::Error` manually (no `thiserror` dependency).
       - `pub fn save_project(project: &ProjectFile, path: &Path) -> Result<(), StoreError>`: serialize pretty, write to `<path>.tmp`, then rename onto `path`. On Windows `fs::rename` fails when the destination exists — if the error kind is `AlreadyExists`, remove the destination and retry the rename once.
       - `pub fn load_project(path: &Path) -> Result<ProjectFile, StoreError>`: read + deserialize, then reject any `schema_version != SCHEMA_VERSION` with `UnsupportedSchema(found)`.
       - Unit tests using `std::env::temp_dir()` + a uuid-suffixed filename, cleaning up afterward: (a) save → load → `assert_eq!` full round trip; (b) a file with `schema_version: 99` yields `UnsupportedSchema(99)`; (c) malformed JSON yields `StoreError::Json`.
    5. Avoid: storing dates as platform-dependent formats. chrono's serde default (RFC 3339) is required for a portable file. Avoid panics in the store — every failure is a `StoreError`.
  </action>
  <verify>`cargo test` runs the three store tests and all pass; `cargo clippy --all-targets -- -D warnings` (if clippy is installed) reports nothing for the new modules</verify>
  <done>AC-1 satisfied (build); AC-5 supported by store error behavior</done>
</task>

<task type="auto">
  <name>Task 3: Navigation shell with organization add / save / open</name>
  <files>src/main.rs, src/app.rs</files>
  <action>
    Turn the proof-of-life window into the Phase 1 shell, using GPUI Kit components.

    1. `src/app.rs` — `pub struct RosterApp` and `pub enum Page { Organizations, Rosters, Employees, Shifts, RosterPlan, Export }`.
       State: `page`, `project: ProjectFile`, `org_name: String`, `project_path: String` (default `"roster-project.json"`), `status: SharedString`, plus `Entity<InputState>` for the organization name and the project path, and `_subscriptions: Vec<Subscription>`.
       Constructor takes `&mut Window, &mut Context<Self>`, builds both inputs with `InputState::new(window, cx)`, and subscribes with `cx.subscribe_in(&input, window, |this, state, event, _, cx| ...)` — on `InputEvent::Change`, copy `state.read(cx).value()` into the matching `String` and `cx.notify()`.
    2. Layout: root `div().flex().size_full()` with a fixed-width left sidebar (`w_56`, border, `p_3`, `gap_2`) and a content column (`flex_1`, `p_6`). Sidebar: app title, one `Button` per `Page` (label from `Page::label()`), the active page using `.primary()`; content below.
    3. Content: `Page::Organizations` renders a `Form` with a `Field` "Organization name" wrapping `Input::new(&self.org_name_input)`, an "Add organization" `Button` that trims and, when non-empty, calls `project.add_organization`, sets status, and `cx.notify()`. Below it, a "Save project" / "Open project" row with `Input::new(&self.project_path_input)` between them. Then the organization list: a `Label` per org, or an empty-state line "No organizations yet" when empty.
    4. Save handler: `store::save_project(&self.project, Path::new(&self.project_path))`; on Ok set status "Saved to <path>", on Err set status "Save failed: <error>". Open handler: `store::load_project(...)`; on Ok replace `self.project`, on Err keep the current project and show "Open failed: <error>" — never `unwrap`, never panic.
    5. Other pages: heading plus "Coming in Phase N" text naming the delivering phase (Rosters/Employees → Phase 5, Shifts → Phase 5, Roster Plan → Phase 6, Export → Phase 8).
    6. Use `cx.theme().background` / `cx.theme().foreground` for base colors so the window respects the theme. Wrap strings in `Label::new(...)` rather than bare `.child("...")` for accessibility.

    Avoid: rebuilding `InputState` inside `render` (state must live on the entity); calling `cx.notify()` before mutating state; blocking file IO inside `render`.
  </action>
  <verify>`cargo build` exits 0; `cargo run` opens the shell; manual: add an organization → appears in list → Save project → file `roster-project.json` exists and contains `"schema_version": 1` → relaunch → Open project → organization reappears</verify>
  <done>AC-2, AC-3, AC-4 satisfied; AC-5 manually confirmed by opening a malformed JSON file</done>
