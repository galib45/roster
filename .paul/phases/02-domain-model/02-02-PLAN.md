<objective>
## Goal

Complete the domain model with per-employee scheduling rules — one-off and recurring unavailability (shift-scoped or whole-day, hard or soft with a penalty), leave periods, recurring assignments — plus roster-level rest rules that generalize the prototype's night→morning rule to any pair of shift templates. Validate cross-references, persist everything, and prove parity with the legacy doctor scenario.

## Purpose

These are the inputs the Phase 3 evaluators and Phase 4 CP model consume. If the rule data is ambiguous or lets dangling shift references through, every later phase inherits the bug. The legacy prototype is the semantic oracle: its weekly/date unavailability, leave, recurring assignments, and night→morning rule must all be expressible without doctor-specific types.

## Output

- `src/domain/constraint.rs`: `Severity`, `Unavailability`, `UnavailabilityScope`, `RecurringAssignment`, `RestRule`
- `Employee` (organization-owned) gains unavailability and recurring assignment lists
- `Roster` gains rest rules; `Organization` gains the APIs that validate employee ↔ roster ↔ shift references
- Constructors that reject unknown employee/roster/shift references, empty rest gaps, invalid leave ranges, and bad penalties
- Full-project persistence tests for every rule type
- `tests/legacy_parity.rs` mirroring `legacy/utils.rs`
</objective>

## Ownership Reminder

```text
Organization
├── positions
├── employees   -> roster_id + position_id
└── rosters
    └── shifts
```

An employee's rules may reference only shifts in the roster named by that employee's `roster_id`. A rest rule belongs to one roster and may reference only that roster's shifts. `Roster` cannot validate these references alone, so the add methods live on `Organization`.

## Legacy Semantics To Generalize
- Weekly unavailability: whole day or one duty category (`WeeklyUnavailability`).
- Date unavailability: whole day or one duty category (`DateUnavailability`).
- Leave: inclusive date range (`DateRange`).
- Recurring assignment: weekday + duty category (`RecurringAssignment`).
- Rest rule: an Emergency Night shift is followed the next day by a prohibited Emergency Morning shift; checked in both directions with the previous-day context (`next_em`/`prev_en` in `legacy/models.rs`).
- Duty hours to reproduce: OPD 6, Emergency Morning 7, Emergency Night 17 (use shift times, not enum variants: OPD 08:00–14:00, Emergency Morning 08:00–15:00, Emergency Night 15:00–08:00).

## Modeling Notes
- Shift references are shift-template ids inside the employee's roster. Whole-day restrictions use an empty `shifts` list; a non-empty list restricts to those shift templates.
- Leave covers every shift on every date in the inclusive range.
- A rest rule is data only in this phase: `min_rest_minutes` is the gap required between the end of an occurrence of `preceding_shift_id` and the start of an occurrence of `following_shift_id`. Evaluation (same-day and next-day) is Phase 3.
- `chrono::Weekday` serializes natively because the `serde` feature is enabled.

## AC-1: Unavailability covers both legacy dimensions and severity
```gherkin
Given organization "City Hospital" with roster "Doctors", employee "Dr. Amit" (roster_id = Doctors), and shifts "OPD", "Emergency Morning", "Emergency Night"
When unavailability rules are added for Dr. Amit through the organization
Then a weekly whole-day rule accepts a weekday and an empty shift list
And a weekly or date rule accepts a non-empty shift list to restrict it to specific shifts in the Doctors roster
And a leave rule accepts an inclusive start/end date range and covers all shifts
And a soft rule records severity Soft plus a positive penalty, while a hard rule records severity Hard with penalty 0
And unknown employee ids, shift ids from another roster, blank shift ids, a leave range with start after end, a soft rule with penalty 0, and a hard rule with a non-zero penalty are rejected
```

## AC-2: Recurring assignments and rest rules are validated
```gherkin
Given organization "City Hospital" with roster "Doctors" containing shifts "Emergency Night" and "Emergency Morning" and roster "Nurses" containing "Day"
When a recurring assignment (Dr. Amit + weekday + Doctors shift) and a rest rule (Emergency Night → Emergency Morning, minimum rest, severity, penalty) are added
Then both receive ids and are stored on the employee/roster respectively
And a recurring assignment with an unknown employee, an unknown shift, or a shift from another roster is rejected
And a rest rule on an unknown roster, with an unknown preceding/following shift id, or with a zero minimum rest is rejected
And a soft rest rule requires a positive penalty, a hard one requires 0
```
