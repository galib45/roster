<objective>
## Goal

Add roster-level sharing groups and a workload report that turns a plan's assignments into per-employee minutes, per-group averages, and a fairness deviation — so the app can show whether a roster is equitable, and Phase 4 has one agreed measure to optimize.

## Purpose

Fairness is the product's differentiator, but 03-01 only reports legal/illegal. Equal headcounts are not equal workload: a night is 1020 minutes against a 360-minute OPD. Sharing groups let departments average workloads across staff who cover for each other, and a single deviation number gives the live editor and the solver the same target.

## Output

- `SharingGroup` domain type, `Roster.sharing_groups`, and a validated `Organization::add_sharing_group`
- `src/eval/fairness.rs`: `WorkloadReport`, per-employee and per-group workload
- `Evaluation.workload` populated by `evaluate`
- `tests/fairness.rs` plus store coverage for persisted groups
</objective>

<design>
## Sharing groups

```text
Roster
└── sharing_groups: Vec<SharingGroup>
    └── SharingGroup { id, name, employee_ids: Vec<String> }

Organization::add_sharing_group(roster_id, name, members: &[&str]) -> Result<&SharingGroup, DomainError>
Roster::sharing_group(id) -> Option<&SharingGroup>
Roster::sharing_group_for_employee(employee_id) -> Option<&SharingGroup>
```

Rules:
- Name is trimmed, blank rejected, duplicate roster-scoped names rejected.
- At least one member; duplicate member ids are removed, first occurrence wins.
- Every member must exist, belong to the owning roster, and belong to no other group in that roster.
- `validate()` re-checks ids, names, membership, and cross-group duplication for hand-edited files.

## Workload report

```text
WorkloadReport {
  employees: Vec<EmployeeWorkload {
    employee_id, minutes: u32, shift_count: u32, group_id: Option<String>
  }>,
  groups: Vec<GroupWorkload {
    group_id, name, member_count, total_minutes: u64,
    average_minutes: f64, deviation_minutes: f64
  }>,
  roster_total_minutes: u64,
  roster_average_minutes: f64,
  deviation_minutes: f64,   // fairness score: lower is better
  max_minutes: u32,
  min_minutes: u32,
}

evaluate(...) -> Evaluation { violations, total_slots, unfilled_slots, workload }
```

Measure:
- Minutes are summed from filled slots in the plan only; previous-day context is excluded because it lies outside the period being generated.
- Every employee in the owning roster appears, including employees with zero assignments.
- An employee's comparison mean is their sharing group's average; ungrouped employees compare against the roster average.
- `deviation_minutes` is the sum of |employee minutes − comparison mean| across the roster.
- A `GroupWorkload.deviation_minutes` is the same sum within that group.
- Results are deterministic: employees sorted by employee id, groups by group id.
</design>

<acceptance_criteria>

## AC-1: Sharing groups are defined and isolated by roster
```gherkin
Given a Doctors roster with four employees
When two sharing groups are added with two members each
Then both groups are stored on the Doctors roster with unique ids and their members
And an employee can be found through their group and a group through its id
And blank names, duplicate group names, empty membership, unknown employees, employees from another roster, and an employee already in a group are rejected
And validate() rejects hand-edited duplicate membership or a dangling member
```

## AC-2: Workload is measured from dated assignments
```gherkin
Given a plan with filled and unfilled slots
When workload is computed
Then each filled seat adds its dated shift's duration to that employee's minutes and increments their shift count
And every roster employee appears, with zero minutes when unassigned
And unfilled slots and previous-day context add no minutes
And total/every-employee minutes reconcile with the plan's durations
```

## AC-3: Sharing groups drive the fairness deviation
```gherkin
Given two employees in one sharing group with 720 and 1020 assigned minutes
When workload is computed
Then each employee's comparison mean is the group average (870) and the group deviation is 300
And an ungrouped employee is compared against the roster average
And a perfectly balanced roster has deviation 0 while an unbalanced roster has a larger deviation
And legacy duty lengths (360/420/1020) produce proportional, duration-weighted results
```

## AC-4: Evaluation exposes workload alongside violations
```gherkin
Given a plan evaluated by evaluate()
When the plan has assignments and sharing groups
Then evaluation.workload matches the standalone workload computation
And unfilled plans report zero minutes and zero deviation for every roster employee
And evaluate() remains read-only
```

## AC-5: Groups persist losslessly and remain compatible
```gherkin
Given a project with sharing groups and a plan
When the project is saved and loaded
Then the groups round-trip with ids, names, and members
And a v2 file without a "sharing_groups" field loads with an empty list
```
