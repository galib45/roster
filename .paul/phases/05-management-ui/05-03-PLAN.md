## Employee dialog state (in `src/app.rs`)

```rust
show_employee_dialog: bool,
editing_employee_id: Option<String>,
employee_name_input: Entity<InputState>,
employee_skills_input: Entity<InputState>,
employee_position_select: Entity<SelectState<SearchableVec<String>>>,
employee_roster_select: Entity<SelectState<SearchableVec<String>>>,
```

On Add/Edit, rebuild the two Select states from the selected organization's position and roster **names** (unique by domain rules), preselect the current value with `IndexPath::new(index)` when editing, and store the entities. Save reads `selected_value()`; map the name back to the id with `organization.positions/rosters`.

## Shift dialog state (in `src/app.rs`)

```rust
show_shift_dialog: bool,
editing_shift_id: Option<String>,
shift_name_input: Entity<InputState>,
shift_roster_select: Entity<SelectState<SearchableVec<String>>>,
shift_start: Entity<TimeFieldState>,
shift_end: Entity<TimeFieldState>,
shift_weekdays: [bool; 7],                 // Mon..Sun
shift_requirements: Vec<ShiftRequirementDraft>,

pub struct ShiftRequirementDraft {
    pub position_select: Entity<SelectState<SearchableVec<String>>>,
    pub headcount_input: Entity<InputState>,
}
```

- Roster is required because shifts are roster-owned.
- Add Row creates both entities via `cx.new(...)`; Remove Row drops that row.
- Weekdays use `gpui_kit::component::checkbox::Checkbox`, label Mon–Sun, `on_click` updates `shift_weekdays`.
- Times use `gpui_kit::component::time_field::TimeField` and `TimeFieldState::time()` / `set_time()`.
- On edit, prefill name, roster, times, weekdays, and one row per stored requirement.

## Domain helpers (additive, tested)

```rust
impl Organization {
    pub fn update_shift(
        &mut self,
        roster_id: &str,
        shift_id: &str,
        name: &str,
        start: NaiveTime,
        end: NaiveTime,
    ) -> Result<(), DomainError>;

    pub fn set_shift_requirements(
        &mut self,
        roster_id: &str,
        shift_id: &str,
        requirements: &[(String, u16)],
    ) -> Result<(), DomainError>;
}
```

- `update_shift`: trim name; reject blank, equal start/end, and a duplicate name among *other* shifts in the roster.
- `set_shift_requirements`: validate roster/shift, every position, and `headcount != 0`; replace `required_positions` exactly. Duplicate position ids collapse to the last value (the UI rejects duplicates before calling).
- These keep validation in the domain instead of mutating `ShiftTemplate` from the UI.

## Validation rules (UI, surfaced in `status`)

- Employee: name non-empty; a position and a roster must be selected; skills are split on commas, trimmed, empties dropped. Write them by clearing `employee.skills` and calling `Employee::add_skill` for each label so trimming and duplicate rules stay in the domain.
- Shift: name non-empty; roster selected; start ≠ end; at least one weekday; at least one requirement row; each row has a selected position and a parsed headcount ≥ 1; no duplicate positions.
- Any failure leaves the dialog open and mutates nothing.
