# Phase 5 Plan 05: Organizations Slice

<objective>

## Goal

Deliver organization management as one complete feature: add, rename, and delete organizations through an inline page form, backed by small `ProjectFile` methods that do the actual work.

## Purpose

This is the first vertical slice. It proves the pattern the rest of Phase 5 follows:

- The domain method is written next to the behavior it owns.
- The page calls that method directly.
- The feature ends usable; no half-built modal state is left behind.

The current Organizations page still uses a `Dialog` to rename and has no delete. Both go away.

## Output

- `ProjectFile::organization`, `organization_mut`, `rename_organization`, and `remove_organization`.
- An inline Organizations page with one form for add/edit and a Delete action per row.
- No organization dialog state in `RosterApp`.
- A smoke-test assertion for rename and delete.

## AC-1: Organizations are added and renamed inline
```gherkin
Given the Organizations page
When I type a name and click Add organization
Then the organization appears in the Organizations list and under Organizations in the sidebar
And the sidebar stays at the Organizations level until the name is clicked
When I click Edit on a row, change the name, and click Save
Then the row shows the new name
And no dialog opens at any point
And a blank name is rejected with a status message and stores nothing
```

## AC-2: Organizations can be deleted
```gherkin
Given an organization with positions and templates
When I click Delete on its row
Then the organization and everything it owns is removed
And the selection moves to another organization or becomes empty
And the change is persisted on the next save
```

## AC-3: The feature round-trips
```gherkin
Given two organizations, one renamed and one deleted
When the project is saved and loaded
Then the renamed organization keeps its new name and the deleted organization is gone
```

## AC-4: Workspace is green
```gherkin
When cargo fmt, build, test, and clippy run
Then all pass with no warnings
And the app still launches
```

  <name>Task 1: Add small ProjectFile organization methods</name>
  <files>src/domain/project.rs, src/domain/error.rs</files>
  <action>
    - Add `organization(&self, id: &str) -> Option<&Organization>` and `organization_mut(&mut self, id: &str) -> Option<&mut Organization>`.
    - Add `rename_organization(&mut self, id: &str, name: &str) -> Result<(), DomainError>`: trim the name, reject blank with `DomainError::BlankName`, return `UnknownOrganization { id }` if the id does not resolve, otherwise update the name and `saved_at`.
    - Add `remove_organization(&mut self, id: &str) -> Option<Organization>`: remove and return the organization, or `None`. Cascading is automatic because positions, employees, templates, and dated rosters live inside it.
    - Add `UnknownOrganization { id: String }` to `DomainError` with a clear `Display` message. Do not add a duplicate-name rule; organizations may share a name.
    - Keep `add_organization` as-is.
  </action>

<task type="auto">
  <name>Task 2: Rewrite the Organizations page as an inline form</name>
  <files>src/ui/organizations.rs, src/app.rs</files>
  <action>
    - Remove `show_org_dialog` and `org_edit_input` from `RosterApp`; reuse `org_name_input` for both add and edit. Keep `editing_org_id: Option<String>`.
    - In `select_org`, clear `editing_org_id` and delegate dialog cleanup to `close_dialogs`.
    - Render one form row: the name input, a primary button whose label is "Add organization" or "Save", and a Cancel button while editing.

    - Keep the file row (Save project / Open project). Positions no longer render here; they are a level-two sidebar page.
    - Update the list row to show name, position count, template count, and Open/Edit/Delete buttons. "Open" calls `open_org` so the sidebar switches to that organization.
  </action>
