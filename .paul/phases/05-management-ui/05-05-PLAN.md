# Phase 5 Plan 05: Inline Management UI

<objective>

## Goal

Rebuild the management UI on the 05-04 model using inline page forms only: Organizations, Positions, Employees, Roster Templates (with nested shifts and staffing requirements), and dated Rosters created with a start/end range. No add/edit dialogs remain.

## Purpose

The approved workflow is a single page-by-page configuration flow, not a sequence of modal dialogs:

1. Create an organization.
2. Add positions and employees for those positions.
3. Define roster templates with the positions they cover, staff exclusions, shifts, and requirements.
4. Create a dated roster from a template by choosing start and end dates.
5. Generate, edit with live metrics, and finalize (Phases 6–7).

This plan delivers steps 1–4 and leaves a stable `Roster Plan` page for generation/editing in Phase 6/7.

## Output

- `Page` enum updated: Organizations, Positions, Employees, Roster Templates, Rosters, Roster Plan, Export; the separate Shifts page is removed.
- Inline add/edit forms on every management page; no `Dialog` imports or `show_*_dialog` state.
- Employees have a position select and skills, with no roster select.
- Roster Templates page: template create/select, position inclusion checkboxes, auto-included staff with exclusion toggles, and inline shift editor (times, weekdays, requirements).
- Rosters page: create a Draft dated roster from the selected template with start/end date inputs; list dated rosters and their status.
- `tests/management_ui.rs` updated for the inline-era configuration and schema v3 round-trip.

## Page structure

| Page | Contents |
|------|----------|
| Organizations | Organization list, select, inline add/edit form |
| Positions | Positions for the selected organization, inline add/edit |
| Employees | Employees for the selected organization, inline add/edit with position select and skills; no roster field |
| Roster Templates | Template list, inline template create/edit; selected template detail with position inclusion, staff exclusions, and nested shifts/requirements |
| Rosters | Dated roster list grouped by template, inline create form (template + start/end dates), status |
| Roster Plan | Placeholder for the selected dated roster; Phase 6 adds generate and Phase 7 adds the editor |
| Export | Placeholder until Phase 8 |

`Page` becomes a `Copy` enum with these seven variants; `Page::Shifts` is removed and its icon reused for Roster Templates. The sidebar keeps the same component and active-state behavior.

## Inline editing pattern

- Every page has a form region and a list region.
- Add starts a blank draft in the form. Edit loads the entity into the same form and sets `editing_*_id`.
- Save validates, applies through the domain, calls `save_project`, clears the draft, and reports in `status`.
- Cancel only clears the draft and `editing_*_id`; it never mutates or saves.
- No `Dialog` import and no `show_*_dialog`/`render_*_dialog` state remains.
- Rows use the existing `Label`/`Button`/`v_flex` patterns; editing a row is just populating the form above it.

## Roster Templates page

- Template name input + Add/Save/Cancel.
- Selecting a template sets `selected_template_id`.
- Position inclusion: a checkbox per organization position; toggling calls `include_position`/`remove_position` (add the latter to `Organization` in this plan if missing) and saves.
- Staff membership: list `template_members(template_id)`; each shows name + position. A checkbox toggles `exclude_employee`/`include_employee` and saves. Excluded staff remain visible in a separate "Excluded" list with an Include button.
- Shifts: list name, HH:MM–HH:MM, weekdays or "Every day", and requirement lines. Add/Edit opens an inline shift form with:
  - name input,
  - two `TimeField` widgets (`TimeFieldState::time` / `set_time`),
  - seven weekday `Checkbox`es,
  - a dynamic `Vec<ShiftRequirementDraft>` with position `Select` + headcount `Input` + Remove, plus Add Row.
- Shift save resolves names to ids and calls `add_shift`/`update_shift` + `set_shift_weekdays` + `set_shift_requirements` on the selected template.
- All seven weekdays normalize to an empty list (the canonical "every day").
- Validation: template name non-empty/unique; at least one position included; every requirement position is included; times differ; at least one weekday; at least one requirement; headcount ≥ 1; no duplicate requirement positions.

## Employees page

- Inline form: name, position `Select`, skills input (comma-separated).
- Save maps the selected position name to its id; add calls `add_employee(name, position_id)`; skills are cleared and re-added through `Employee::add_skill`.
- The list shows position and skills; no roster reference anywhere.

## Rosters page

- Template selection (reuse the selected template from the Roster Templates page or a select on this page).
- Create form: start date and end date as text inputs (`YYYY-MM-DD`, parsed with `NaiveDate::parse_from_str`), plus optional previous-day context entry deferred to Phase 6 — for now create with empty context.
- Save calls `create_roster(template_id, start, end, Vec::new())`, which snapshots members and expands dated shifts, and saves.
- List each dated roster with template, date range, status (Draft/Generated/Finalized), and a Select button that sets `selected_roster_id` for the Roster Plan page.
- No solver invocation in this plan.

## Roster Plan page

- Empty state when no dated roster is selected.
- Otherwise show template name, date range, status, member count, dated shift count, and a note that Generate arrives in Phase 6 and live editing/finalize in Phase 7.
- No generation button yet.
