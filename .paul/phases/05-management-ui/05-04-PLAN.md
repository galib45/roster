# Phase 5 Plan 04: Simplify the Foundation

<objective>

## Goal

Cut the codebase down to the smallest foundation that still supports the template + dated-roster model: one schema version with no migration path, no deep `validate()` sweep, and a small smoke test suite. The app must still build, test, and launch.

## Purpose

The current code is hard for a solo developer to hold in their head, and much of it does not serve the MVP:

- `src/domain/migration.rs` is 548 lines that convert v1/v2 files that only exist on this machine.
- `Organization::validate()` is a multi-hundred-line defensive scan used only by tests, not by the running app.
- `cargo check --all-targets` fails with 33 errors because six integration suites still build the pre-template model.
- The old `roster-project.json` is a v2 file that the app will stop accepting.

Removing this now makes every later slice smaller. Real migrations come back after the MVP, when the schema has settled.

## Output

- No `src/domain/migration.rs`; the store reads only the current schema version.
- No `Organization::validate()`, duplicate-id scan, or dangling-reference guards.
- A `tests/smoke.rs` that proves one project round-trips and the solver still runs.
- A green `cargo fmt`, `cargo build`, `cargo test`, and clippy run.
