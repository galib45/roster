# 05-01 UAT: Management UI Verification Issues

## Test Date: 2026-11-18

## Summary

Phase 5 Management UI implementation has the page structure and navigation, but **functional CRUD forms are missing**. The UI elements for creating/editing organizations, rosters, employees, and shifts are largely placeholders without working input fields.

---

## Issues Found

### UAT-001: Organization Edit Dialog Missing Fields
**Severity:** Blocker
**AC Reference:** AC-1 (Organization CRUD)

**Description:** The Organization page has an "Add organization" form with a name field, but clicking "Edit" on an existing organization only sets draft state without showing a dialog with the name field pre-filled and editable.

**Steps to Reproduce:**
1. Start app
2. Add an organization "City Hospital"
3. Click "Edit" button next to it
3. No dialog appears; only draft state is set internally

**Expected:** Edit dialog should appear with name field pre-filled, allowing modification.

---

### UAT-002: Roster Add Dialog Is Placeholder Only
**Severity:** Blocker
**AC Reference:** AC-2 (Roster CRUD with staff isolation)

**Description:** The Rosters page has an "Add roster" button that shows "Roster creation form coming soon" label instead of a functional form with name input.

**Steps to Reproduce:**
1. Navigate to Rosters page for an organization
2. Click "Add roster" (or see the add row)
3. See "Roster creation form coming soon" label instead of form

**Expected:** Functional form with roster name input field and Save/Cancel buttons.

---

### UAT-003: Employee Add/Edit Form Missing Fields
**Severity:** Blocker
**AC Reference:** AC-3 (Employee CRUD with position/roster validation)

**Description:** The Employees page shows "Employee creation form coming soon" label instead of a functional form. The edit button sets draft state but no dialog appears with pre-filled fields.

**Missing Fields:**
- Name (text input, required)
- Position (select dropdown from organization positions)
- Roster (select dropdown from organization rosters)
- Skills (text input, comma-separated, optional)

**Steps to Reproduce:**
1. Navigate to Employees page
2. Click "Add employee" or "Edit" button
3. See "Employee creation form coming soon" label

**Expected:** Functional form with all required fields, validation, Save/Cancel buttons.

---

### UAT-004: Shift Add/Edit Form Missing Fields
**Severity:** Blocker
**AC Reference:** AC-4 (Shift CRUD with requirements)

**Description:** The Shifts page shows "Shift creation form coming soon" label instead of a functional form.

**Missing Fields:**
- Shift name (text input, required)
- Start time (time picker, required)
- End time (time picker, required)
- Weekdays (checkboxes Mon-Sun, at least one required)
- Requirements table: Position (select), Headcount (number ≥1), Add/Remove rows

**Steps to Reproduce:**
1. Navigate to Shifts page
2. Click "Add shift" or "Edit" button
3. See "Shift creation form coming soon" label

**Expected:** Functional form with all fields including dynamic requirements table.

---

### UAT-005: No Save/Cancel Actions on Detail Pages
**Severity:** Major
**AC Reference:** AC-5 (Validation and unsaved changes)

**Description:** Detail pages (EmployeeDetail, RosterDetail, ShiftDetail) show draft state but have no Save/Cancel buttons to commit or discard changes.

**Steps to Reproduce:**
1. Click Edit on an employee (sets draft)
2. No Save/Cancel buttons appear to commit/discard

**Expected:** Save button validates and persists; Cancel discards draft.

---

### UAT-006: Position/Roster Dropdowns Not Connected to Validation
**Severity:** Major
**AC Reference:** AC-3, AC-2

**Description:** Position and Roster select dropdowns exist in draft code but are not rendered in actual forms. No validation prevents invalid selections.

**Expected:** Dropdowns populated from organization's positions/rosters; validation on Save.

---

### UAT-007: Requirements Table for Shifts Not Implemented
**Severity:** Major
**AC Reference:** AC-4

**Description:** Shift requirements (position + headcount rows with Add/Remove) are completely absent.

**Expected:** Dynamic table with Add/Remove row buttons, position select, headcount number input.

---

### UAT-008: Weekday Selection for Shifts Not Implemented
**Severity:** Minor
**AC Reference:** AC-4

**Description:** Weekday checkboxes (Mon-Sun) for shift recurrence not implemented.

**Expected:** 7 checkboxes, at least one required.

---

### UAT-009: Time Picker for Shift Start/End Not Implemented
**Severity:** Minor
**AC Reference:** AC-4

**Description:** Shift start/end time fields use plain text input instead of time picker.

**Expected:** Time picker component (HH:MM format).

---

### UAT-010: Skills Field Not Properly Parsed/Stored
**Severity:** Minor
**AC Reference:** AC-3

**Description:** Skills input exists in draft but not connected to form; comma-separated parsing not verified.

**Expected:** Comma-separated skills parsed into Vec<String> on save.

## Impact

The Management UI (Phase 5) has the **navigation structure** but lacks **functional forms**. Users cannot actually create or edit the core entities (rosters, employees, shifts) that the solver needs.

**Phase 5 cannot be considered complete** until Blocker issues are resolved.

---

## Recommendation

Create a FIX plan targeting all Blocker and Major issues first, then Minor issues.
